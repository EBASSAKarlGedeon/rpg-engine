Route the game's AI calls through the Loreweaver server, using one of your Connection Manager profiles — the same connections the chat uses. The API key is resolved server-side from the profile's stored key and never enters this page. Streaming works.

Leave a job on (main profile) to use the main profile above. Assign a different profile to a job to run it on that connection instead — e.g. trackers, checks and memories on a cheap model, the GM on your best one.

How much of the model's context window the game may use per prompt — roughly your model's context window (e.g. 32768, 65536, 131072). The game fills this with as much recent story + lore + memories as fits instead of capping itself at Perchance's small window. Too high for the actual model: the API truncates or errors.

How it works

  1. The main profile decides everything for unrouted calls: endpoint URL, model, and API key (its secret-id entry in Loreweaver's server-side key store).
  2. The game's Settings > AI Model base URL and model are ignored while the bridge is on (its key field can stay anything). The game's own per-job toggles (Settings > AI Model > External AI calls) still decide whether a job calls the external provider at all — off falls back to Perchance AI as before.
  3. The cheap secondary model (cheap-model.html) is its own row in the per-job list; leave it on the main profile or give it its own cheap connection.

Only works when this page is served by Loreweaver (same origin). Keep the bridge off for standalone use (python http.server).
